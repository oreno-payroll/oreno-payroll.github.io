# Payroll（ローカル給与明細管理）

本業・副業の給与と賞与を、PDF原本と一緒にブラウザのIndexedDBへ保存します。アプリから給与データを外部APIに送信しません。

## 画面・実装

- `src/main.ts`：ホーム画面、支給額集計と保存済みPDF一覧、年度末までの見込み表示
- `src/forecast/annualForecast.ts`：保存データを変更しない、直近通常給与の中央値による年度見込み計算
- `src/upload.ts`：複数PDFの解析、入力確認、重複スキップ付き一括保存
- `src/edit.ts`：保存済み明細の編集。古いタブからの上書きを防止
- `src/backup.ts`：暗号化バックアップ作成、旧ZIP/暗号化形式の復元
- `src/pdf/`：PDF.jsによる座標診断・給与/賞与の書式解析
- `src/storage/`：IndexedDB、入力検証、ZIP、暗号化、保存容量管理、PDF原本検査
- `public/`：HTMLとCSS。`dist/`はビルド生成物なので編集しません

## Macでの実行

```bash
npm ci
npm run check
npm run build
npm run dev
```

Live Serverは `dist/index.html` を開いてください。`127.0.0.1`と`localhost`、異なるポートはそれぞれ別のIndexedDBになります。

## 保存・重複

- 1回のアップロードでは最大30件、各PDF最大25MiB。保存済み原本は1件最大50MiB（旧データとの互換）。原本の合計容量は最大480MiB、明細は最大2000件です。
- 同一PDF（SHA-256）または「勤務先・明細種別・対象年月」が一致すると重複扱いになります。
- **既存データを優先し、重複分だけスキップ**。10件中1件が既存データと重複すれば、新規9件だけ保存し、保存後にスキップした項目を通知します。
- 同時投入の中に重複があれば、先に並んだ1件を保存して、後の重複をスキップします。
- 既存データや手動編集済みの金額、PDF原本を重複保存で置換しません。
- 一括登録は単一のIndexedDBトランザクションで実施します。保存に失敗すれば今回の登録分はロールバックされます。
- 保存済み明細を編集すると更新番号が進みます。別タブで編集が確定していた場合、古いタブからの保存を拒否します。
- 編集画面で年月・種類を変更して別の保存済み明細に重なったときの既存の確認・完全置換機能は引き続き存在します。これはアップロード時のスキップ処理とは別です。

## 暗号化バックアップ（v1）

- 1個の従来ZIP（`manifest.json` と `pdf/`原本）をブラウザ標準の **AES-256-GCM** で丸ごと暗号化します。
- 鍵導出は **PBKDF2-HMAC-SHA256・600,000回、ランダムsalt 16バイト**。GCM nonce/IVはファイルごとに乱数12バイト。ヘッダーは認証追加データ（AAD）で保護します。
- 書出ファイルの拡張子は `.payroll`。一般のZIP解凍ソフトでは直接開けません。パスワードはアプリ・IndexedDBには保存されず、忘れると復元できません。
- **以前作成した無暗号 `.zip` もインポート可能**。ZIP内部のschemaVersionは1のままです。
- 復元時は復号→ZIP構造/CRC→PDFのSHA-256→PDF.jsでの解析→メタデータ・金額・容量チェックの後、ユーザーの確認を経てIndexedDB全件置換します。
- 最大ZIP 512MiBに対して保存可能PDF合計を480MiB以下に制限し、保存済みでバックアップ不能になる事態を防ぎます。
- ZIP生成・暗号化・復元では、一時的に原本と同程度以上のメモリを使用します。大容量バックアップにはメモリ余裕のある端末を使ってください。
- バックアップの暗号化は**IndexedDBの暗号化とは別**です。閲覧するブラウザやオリジンの管理にも注意してください。

## 安全運用

- 最初に現在のデータを旧版でバックアップし、安全な場所へ保管してから更新してください。
- 新版の `.payroll` を作成後、**別のブラウザプロファイルなどの空の環境でテスト復元**できると安心です。既存データがある状態で安易に全件復元しないでください。
- 本アプリはサーバーへ自動保存しません。ブラウザのサイトデータ削除に備え、定期的にバックアップしてください。
- `node_modules`、`dist`、PDF原本、ZIP、`.payroll` はGit管理に含めない設定です。

## 年度見込み（ホーム専用）

ホームの「3月まで見込み」をONにすると、現在年度の未登録の通常給与を、勤務先別の直近3件の中央値を使って表示用の合計に加算します。本業のみ8月・翌2月の未登録賞与を、月給の交通費と立替経費を除いた額面・手取りを用いて参考推計します。既に登録済みの本業賞与がある月には加算しません。副業の将来賞与は予測しません（保存済みの副業賞与実績は「賞与を含む」ON時に集計）。通常給与の過去未登録月は補完しません。チェック状態と見込み額は保存されません。

## 例外帳票と個別確認（2026-11-12）

- 本業の「通勤手当/非課」「非課税通勤費」と「立替経費」が同月に存在するときは、**交通費と立替経費を別々に保存**します。税区分の帳票検算では、両者の合計を非課税支給額として使います。
- 本業に「立替経費」しか存在しない場合は、交通費として全額保存し、経費欄は空欄にします。経費と交通費の内訳は推測しません。
- 将来の月給予測では経費精算を繰り返すと仮定せず除外し、本業賞与の見込みでは交通費・経費の両方を除外します。
- 既に保存済みの明細の内訳は自動的に書き換えません。編集画面で交通費・立替経費の項目を修正できます。
- 「年調過不足税額」は通常の所得税と独立して保存する任意フィールドです。負数（還付）を認め、手取り検算の控除内訳にも含めます。ホームの所得税実績は年調を加味し、将来の月給見込みは年調額を参照しません。
- 本業の賞与が0円で、賞与手当・所得税・振込欄が存在しない明細も、上部の差引0円と支給・控除各0円を確認できれば正常な「要確認」明細として保存できます。入力に存在しない控除額を勝手に書き込むことはしません。
- アップロード画面の「要確認」「確認済み」はPDFごとに管理します。警告を確認した明細は別の明細を開いても状態を維持し、当該明細を編集した場合のみ確認を解除します。**警告がある全件を確認済みにするまで一括保存はできません**。
- 現在の確認状態はアップロード画面内の未保存一時状態です。保存すると確認記録は明細ごとにIndexedDBへ保存されます。
